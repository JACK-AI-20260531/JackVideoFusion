## 1. 背景与问题

### 1.1 竞品现状
- Descript 以"**编辑转写文本 = 剪辑视频**"为核心范式(删字即删片段、Regenerate 修补剪坏的点),订阅 $16-50/月;
- 剪映"智能剪口播"已免费实现"按文本删口播"的初级版;
- InVideo AI 证明**对话式改片**("把第 3 段换成科技感画面")的留存显著高于一次性生成。

### 1.2 我们的现状与差距
- 已具备全部底料:`asr`(Whisper 转写 + SRT)、`shot-detect`(镜头表)、`ffmpeg`(切割)、`video-mix`(多段合成渲染)、`llm`(指令解析)、`task-queue`(断点续渲);
- 差距:文本与时间线**互相独立**——用户看得到转写字幕却不能"点着字剪",改一次要回素材页重跑,普通用户上手门槛高。

### 1.3 机会
把"AI 混剪/AI 切片"的产出物从**黑盒成片**升级为**可对话、可文本编辑的草稿(EDL)**。这是交互革命,也是护城河:巨头做不了深度(生态利益),单机工具做不了(无本地 ASR/LLM 栈),而我们两端都有。

---

## 2. 目标与非目标

### 2.1 目标
1. 口播/解说类视频:转写文本与时间线**双向绑定**——点文字跳画面、选中删句、删口头禅、压缩停顿;
2. 所有编辑操作落到**非破坏性 EDL(编辑决策列表)**,不碰原素材;
3. 对话式改片:聊天指令("这段太长,剪到 15 秒""把口头禅都删掉")→ 生成编辑计划 → 预览 diff → 一键应用重渲。

### 2.2 非目标
- 不做通用多轨 NLE 时间线(拖拽轨道、关键帧等仍由专业软件承担);
- 不做实时画面级预览渲染(v1 只做**代理低清预览** + 最终渲染);
- 不承诺字词级(word-level)精确到毫秒的剪辑,句级为准、词级尽力。

## 4. 功能需求

### 4.1 文本-时间线双向绑定(P0)

**FR-1 转写即轨道**
- AI 混剪/口播工程打开时,自动跑 `asr` 生成句级转写:`TextSegment { id, text, start, end, speaker? }`;
- 若 ASR 引擎支持词级时间戳则附带 `words[]`(尽力而为,不阻塞);
- 文本面板与视频预览双向联动:点击文本 → 预览 seek;播放到某句 → 对应文本高亮滚动。

**FR-2 文本编辑操作集**
| 操作 | 行为 | 映射到 EDL |
|------|------|-----------|
| 删除句 | 选中一句按 Delete | `cut(start,end)` |
| 静音段 | 选中文字置灰 | `mute(start,end)` |
| 删除口头禅 | 一键(词表:嗯/啊/然后/就是/那个,可自定义) | 批量 `cut` |
| 压缩停顿 | 一键(>0.8s 的静音段压到 0.2s) | 批量 `cut` |
| 段落重排 | 拖动段落 | `move(srcRange,dstIndex)` |

**FR-3 非破坏性 EDL**
- 所有操作只修改 EDL;随时可"还原到原始";导出时经 `video-mix` 一次性合成。

### 4.2 对话式改片(P1)

**FR-4 编辑计划生成**
- 聊天输入 → LLM 输出**结构化编辑计划**(op 列表,受 JSON schema 约束):
  ```ts
  type EditOp =
    | { op: 'cut'; start: number; end: number; reason: string }
    | { op: 'mute'; start: number; end: number; reason: string }
    | { op: 'move'; srcStart: number; srcEnd: number; dstIndex: number; reason: string }
    | { op: 'retune'; param: string; value: string; reason: string };
  ```
- UI 呈现为**可勾选的 diff 清单**(每条 op 显示范围+理由),用户确认后应用;不支持/有歧义的指令,Agent 反问澄清而不是猜。

**FR-5 撤销/重做**
- EDL 变更走命令栈(命令模式),至少保留 20 步;每次"应用计划"作为一条复合命令。

## 5. 交互设计

```
┌───────────────────────────────────────────────┐
│  [预览窗(代理画质)]              │ 💬 对话框      │
│   ▶ 00:42 / 10:00               │ 你:删掉口头禅   │
├──────────────────────────────────────────────┤
│  📝 文本面板                                    │
│  ██ 大家好,今天聊聊剪辑。01:02-01:05            │
│  ██ ▓嗯,gpt-sovits ██ 的效果…   [已删除:2 句]  │
│  ██ 接下来看第二个案例。02:10-02:15             │
├──────────────────────────────────────────────┤
│  ⏱ 时间线缩略(镜头块 + 已删区域灰显)  [导出成片]  │
└──────────────────────────────────────────────┘
```
- 删除的文本划线灰显、可点恢复;
- 时间线只做**缩略条**(镜头块 + 删除区域),不做专业轨道编辑;
- 对话产生的计划 diff 用绿(新增)/红(删除)标记。

## 6. 技术方案

### 6.1 新增服务 `text-timeline`
```
src/main/services/text-timeline/
├── types.ts          # TextSegment / EditOp / EDL
├── transcript.ts     # asr 结果 → TextSegment[](句对齐、词表清理纯函数)
├── edl.ts            # EDL 构建/合并/校验纯函数(cut/mute/move 的区间合并)
├── command-stack.ts  # 撤销/重做命令栈
└── index.ts          # 服务编排:转写→EDL→调用 video-mix 渲染
```

### 6.2 关键决策
1. **非破坏性**:EDL 只是"保留区间 + 变换"清单,导出时映射为 ffmpeg 的 `trim/concat/amute`,复用 `video-mix` 渲染管线与断点续渲;
2. **代理预览**:导入时生成 360p 代理(`ffmpeg` 低码率),预览与对话迭代都打代理,导出才用原画质——把"改一次等 3 分钟"变成"改一次等 5 秒";
3. **对话解析**:复用 `llm` 服务(已有 openai/ollama provider),新增"编辑计划"prompt + JSON 容错解析(沿用 PRD-爆款评分的 schema 校验与降级思路);
4. **区间合并规则**:`cut` 区间相邻自动合并;`mute` 与 `cut` 冲突时 `cut` 优先;所有 op 先在内存 EDL 上 dry-run 校验再入命令栈。

### 6.3 渲染层
- 新组件 `TranscriptPanel.vue` + `EditPlanDialog.vue`,嵌入 `AIEditView.vue`(口播场景)与 `AISliceView.vue`(切片后精修);
- 预览 seek:`<video>` 直接设置 `currentTime`(代理文件),不经过主进程。

### 6.4 测试要求
- `transcript.ts` / `edl.ts` / `command-stack.ts` 纯函数单测全覆盖(区间合并的边界:相邻/嵌套/越界);
- 对话指令→op 的 schema 校验失败与澄清反问路径必须有测试。

## 8. 风险与依赖

| 风险 | 对策 |
|------|------|
| Whisper 词级时间戳不准 | 句级为准;剪辑点向后外扩 0.15s 余量 |
| LLM 生成非法 op | schema 校验 + dry-run 拒绝越界区间 + 反问澄清 |
| 代理生成拖慢首屏 | 转写完成前文本面板显示骨架屏;代理后台生成 |
| 渲染耗时用户无感 | 复用任务中心,进度/断点续渲透出 |
| 依赖项 | 依赖 PRD-爆款评分落地的 llm schema 校验基建;onnxruntime 打包问题需在 v2.0 前修复 |
