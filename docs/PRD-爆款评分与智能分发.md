## 1. 背景与问题

### 1.1 竞品现状
- Opus Clip 以 **Virality Score(爆款指数)** 作为核心卖点,为每条切片输出分数,服务 1600万+ 创作者;
- 剪映的"智能解说粗剪"免费内置,但**不提供任何评分与理由**;
- 百度度加"热点成片"证明:AI 成片本身已不构成付费点,**"数据化的判断力"才是新付费点**。

### 1.2 我们的现状与差距
- `ai-slice/score.ts` 已有启发式精彩度评分:`0.4×场景分 + 0.3×时长分 + 0.3×CLIP分`,归一化 0-1;
- 差距:①评分只有数字、**没有理由与建议**,用户不知道"为什么";②没有标题/标签生成;③定时发布是单次内存延时(`schedule.ts` 仅 18 行),重启即丢、不支持矩阵号批量。

### 1.3 机会
我们的切片已按精彩度降序输出,离"爆款评分"只差**一层 LLM 多维评估 + 可解释 UI**。这是 v1.5 里**实现成本最低、感知最强**的差异化功能。

---

## 2. 目标与非目标

### 2.1 目标(Goal)
1. 每条切片输出 **爆款分(0-100)+ 等级(S/A/B/C)+ 评分理由 + 改进建议**;
2. 每条切片生成分平台风格的 **候选标题(≥5)+ 话题标签 + 封面文案**;
3. 发布升级为 **持久化定时任务**:关掉应用到点也能在下次启动时补发提示;支持多账号矩阵批量发布。

### 2.2 非目标(Non-goal)
- 不做播放量数据回收(平台 API 受限,后续版本考虑);
- 不做付费墙/积分计费(商业模式另行立项);
- 不改动切片算法本身的镜头切分逻辑。

## 4. 功能需求

### 4.1 爆款评分(P0)

**FR-1 多维评分**
- 切片完成后自动(或用户手动点击"智能评分")触发 LLM 评估;
- 评估输入:切片 ASR 文本(复用 `asr` 服务)、镜头时长、场景变化率、CLIP 语义分、原视频标题/文案(如有);
- 输出五维子分(0-100)+ 综合分:

| 维度 | 权重 | 说明 |
|------|------|------|
| 钩子强度 hook | 0.25 | 前 3 秒是否留人(悬念/冲突/反差) |
| 情绪强度 emotion | 0.20 | 情绪曲线峰值与张力 |
| 话题性 topic | 0.25 | 是否踩中热点/共鸣点/争议点 |
| 完播潜力 retention | 0.20 | 节奏、信息密度、时长适配 |
| 标题潜力 titleability | 0.10 | 可提炼出吸睛标题的素材度 |

- 综合分 = Σ(子分×权重),映射 0-100;等级:S≥85 / A≥70 / B≥55 / C<55;
- **每次评分必须输出理由(1-3条)与改进建议(0-2条)**,这是与竞品拉开差距的关键。

**FR-2 评分降级**
- 未配置 LLM → 跳过 LLM 维度,把现有启发式 `excitementScore` 映射为 0-100 基础分,UI 显示"基础评分"标签,不弹错误;
- LLM 调用失败 → 重试 1 次后降级为基础评分,任务不阻塞。

**FR-3 批量评分**
- 一次任务只调用一次 LLM(把所有候选切片摘要合并成一个 prompt),控制 token 成本;
- 单条切片解析失败不影响其余(失败隔离)。

### 4.2 标题 / 标签 / 封面文案(P0)

**FR-4 分平台文案生成**
- 评分通过后顺带生成:`titles[5]`、`tags[8]`、`coverText[3]`;
- 平台风格开关:抖音(强钩子)、小红书(emoji+痛点)、B站(信息量)、视频号(情感向);
- UI 上一键复制,发布时自动带入 `auto-publish` 表单。

### 4.3 持久化定时与矩阵发布(P0/P1)

**FR-5 持久化定时任务(P0)**
- 定时发布落盘(复用 `storage` 服务,JSON 持久化),应用重启后:已过期的任务在任务中心标记"错过发布",一键立即执行;
- `schedule.ts` 从"一次性延时"升级为"调度器轮询 + 状态机"(pending → firing → done/failed/cancelled)。

**FR-6 矩阵号批量(P1)**
- 同一视频勾选多账号(复用 `auth-store` 已存账号),支持设置**发布间隔(错峰)**;
- 入队后由 `publish-queue` 串行执行,单账号失败不影响其他账号,失败可单独重试。

## 5. 交互设计

### 5.1 AISliceView(切片结果卡片)
```
┌─────────────────────────────┐
│ [S 92] ██████████░ 00:12-00:41 │  ← 分数徽章+进度条,S/A 级有彩色角标
│ 🎯 钩子强:前3秒出现冲突台词      │
│ 💡 建议压缩到 25s 内            │
│ ✏️ 智能评分(无LLM时:基础评分)   │
└─────────────────────────────┘
```
- 每卡片新增:分数徽章、等级色(S=红橙/A=橙/B=蓝/C=灰)、理由折叠区、建议;
- 排序开关:按时间线 / 按爆款分;
- "复制标题""复制标签"按钮;顶部"批量评分"入口。

### 5.2 AutoPublishView(发布队列)
- 新增"定时任务"Tab:列表(时间/平台/账号/状态),支持编辑、取消、立即执行;
- 批量发布弹窗:多选账号 + 错峰间隔(默认 10 分钟)+ 失败策略(跳过/重试)。

## 6. 技术方案

### 6.1 数据结构(新增/扩展)
```ts
// ai-slice/types.ts 扩展
interface ViralityReport {
  score: number;            // 0-100
  grade: 'S' | 'A' | 'B' | 'C';
  sub: { hook: number; emotion: number; topic: number; retention: number; titleability: number };
  reasons: string[];
  suggestions: string[];
  titles: string[];
  tags: string[];
  coverText: string[];
  source: 'llm' | 'heuristic';
}

interface SliceClip {
  // ...现有字段
  virality?: ViralityReport;
}
```

### 6.2 模块与调用链
1. `ai-slice/score.ts` 新增纯函数 `mapHeuristicToVirality(score)` 与 `gradeOf(score)`——可单测,不依赖 electron;
2. `ai-slice/virality.ts`(新):组装 prompt(复用 `llm/prompts.ts` 模式)→ 调 `llm` 服务 → 解析 JSON → 字段校验(缺失字段降级);
3. IPC:`ai-slice.ipc.ts` 新增 `ai-slice:scoreVirality`(入参:切片路径+文本摘要列表;出参:`Record<clipIndex, ViralityReport>`);
4. `auto-publish/schedule.ts` 扩展:`computeScheduleDelayMs` 保留;新增 `schedule-store.ts`(持久化 CRUD + 错峰计算纯函数 `staggerQueue(base, accounts, intervalMs)`);
5. 渲染层:`AISliceView.vue` 卡片扩展;`AutoPublishView.vue` 定时 Tab。

### 6.3 测试要求
- 纯函数(prompt 组装、JSON 容错解析、等级映射、错峰计算)单测全覆盖,沿用现有 `__tests__` 风格;
- LLM 超时/返回非法 JSON 的降级路径必须有集成用例。

## 8. 风险与依赖

| 风险 | 对策 |
|------|------|
| LLM 评分不稳定 | 温度调低(≤0.3)、JSON schema 约束、失败降级基础分 |
| token 成本 | 合并单次调用;prompt 只传文本摘要与非必要时长信息 |
| 平台发布风控(矩阵号) | 错峰默认开启;账号频率上限文档化提示 |
| 依赖 onnxruntime 打包问题(遗留) | 评分链路不依赖 onnxruntime;但需跟进修复,避免 ASR 环节走 Mock 影响评分输入质量 |
